# Agile Report: v0.3.2 - Security & Recovery Foundation

## Summary
Successfully implemented a robust authentication system for high-risk operations, including password protection for Tier 0/1 and a secure recovery mechanism.

## Changes

### 1. Authentication Infrastructure
- Created `src/tlm/safety/auth.py` using `PBKDF2-SHA256` for password hashing and high-entropy Master Recovery Keys.
- Updated `UserSettings` to securely persist authentication hashes in `config.toml`.

### 2. CLI Auth Management
- Implemented the `tlm auth` command suite:
  - `set-password`: Interactively sets a master password and generates a unique Master Recovery Key.
  - `recover`: Allows resetting the password using the Master Recovery Key.
  - `status`: Displays current auth configuration.

### 3. Tier-Based Gate Enforcement
- Integrated mandatory password checks for Tier 0 (Root) and Tier 1 (Workspace) operations in `tlm do` and `tlm write`.
- Users are prompted for their password before sensitive execution plans are processed if a password has been set.

## QC Findings
- **Security**: Password salts and high-iteration PBKDF2 ensure resistance to local brute-force attacks.
- **Resilience**: The Master Recovery Key provides a reliable fallback for users who forget their password, preventing permanent lockout.
- **Usability**: Authentication is only required for sensitive Tiers (0/1), keeping low-risk operations (Whitelist/Sandbox) frictionless.
