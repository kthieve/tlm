## Goal

Establish the core security and interaction patterns required for all future "agentic" capabilities.

## Key Features

- **Four-Tier Permission Model** (F1-F3, ✅ complete):
  - **Root (Tier 0)**: High-risk system operations requiring `tlm auth` (maps to `trusted`).
  - **Workspace (Tier 1)**: Full access within project root (maps to `standard`).
  - **Whitelist (Tier 2)**: Restricted to `permissions.toml` (maps to `strict`).
  - **Sandbox (Tier 3)**: Isolated `bwrap`/`firejail` execution.
- **Execution Safety** (F13-F15, ⚠️ partial):
  - **Temporal Snapshotting (The Agent Undo)**: Before any Tier 1/2 change, take a lightweight snapshot.
  - **Perfect Rollback**: `tlm undo` reverts the workspace.
  - **Atomic Transactions**: Multi-file writes staged in `.tlm/tmp` and moved atomically.
- **Security & Recovery** (F6-F9, ✅ complete; F18, ❌ not started):
  - **Password Access**: Optional password for Tier 0/1 operations.
  - **Recovery System**: Master Recovery Key generated during `tlm auth set-password`.
  - **Auth timeout**: Re-authentication after configurable idle period.
- **Interactive Control** (F10-F12, F17, ⚠️ partial):
  - Graceful SIGINT (Ctrl+C) for LLM streams and shell executions.
  - `tlm stop`: Hard-kill runaway processes and clean up temporary stages.

## Sprint Plan

### Sprint 1: Harden Snapshot & Undo (F13, F14)

**Phase A — Plan**: The current `snapshot.py` is **destructive** — it runs `git add .` which stages untracked files and pollutes the user's index. The `undo` command does `git reset --hard` with no confirmation. Both need a non-destructive rewrite.

**Phase B — Build**:

1. **`safety/snapshot.py`** — rewrite:
   - Replace `git add . && git commit` with `git stash create` (creates a stash commit without touching the index or working tree).
   - Store the stash SHA in `.tlm/snapshots/<timestamp>.sha` (not as git tags that pollute the user's tag namespace).
   - Add `list_snapshots(path) -> list[SnapshotInfo]` returning `(id, timestamp, message)`.
   - Add `restore_snapshot(path, snapshot_id)` that uses `git stash apply <sha>` (non-destructive) or `git checkout <sha> -- .` depending on user choice.
   - **Non-git fallback**: Use `shutil.copytree()` of tracked files into `.tlm/snapshots/<ts>/` (capped at 50MB, configurable).

2. **`cli.py`** — enhance `cmd_undo_ns`:
   - `tlm undo` (no args): List recent snapshots (max 10), let user pick.
   - `tlm undo <id>`: Restore specific snapshot with confirmation prompt.
   - `tlm undo --list`: Show all snapshots with timestamps and sizes.
   - `tlm undo --hard`: Skip confirmation (for scripts).
   - `tlm undo --dry-run`: Show what would change without restoring.

**Phase C — Test**: 
- `tests/test_snapshot.py`: Mock `subprocess.run` for git commands; verify `create_snapshot` returns valid IDs, `list_snapshots` returns sorted list, `restore_snapshot` calls correct git commands.
- `tests/test_undo_cli.py`: Test argparse wiring and confirmation flow.

**Phase D — Document**: Update `CODE_INDEX.md` for `snapshot.py` role change.

**Phase E — QC**: Verify no secrets leak; `ruff check`; `mypy`.

**Phase F — Report**: `.cursor/plans/reports/v0.3.0_sprint1_snapshot.report.md`.

**Phase G — Polish**: `ruff format`.

**Files touched**: `safety/snapshot.py`, `cli.py`, `modes/write.py` (snapshot call), `modes/do.py` (snapshot call), `tests/test_snapshot.py` (new), `tests/test_undo_cli.py` (new).

### Sprint 2: Atomic Transaction Manager (F15)

**Phase A — Plan**: Current write mode stages files in `.tlm/tmp` but has no all-or-nothing guarantee. If file 3/5 fails to `os.replace()`, files 1-2 are already moved and file 4-5 never written. Need a proper two-phase commit.

**Phase B — Build**:

1. **`safety/transaction.py`** (new module):
   ```
   class AtomicTransaction:
       def __init__(self, base_dir: Path)
       def stage(self, target: Path, contents: str, mode: int) -> None
       def commit(self) -> list[Path]   # all-or-nothing
       def rollback(self) -> None       # clean up staged files
   ```
   - `stage()`: Write to `.tlm/tmp/<uuid>`, record `(target, tmpfile, mode)` in a manifest.
   - `commit()`: First verify all targets are writable (parent dirs exist, permissions ok). Then `os.replace()` each in sequence. If any fails, copy originals back from backup copies made before the first `os.replace()`.
   - `rollback()`: Remove all staged files and manifest.

2. **`modes/write.py`** — refactor to use `AtomicTransaction`:
   - Replace the inline staging logic (L166-201) with `AtomicTransaction`.
   - Snapshot is created before `txn.commit()`, rolled back on failure.

**Phase C — Test**: `tests/test_transaction.py` — stage 5 files, commit, verify all exist. Simulate failure on file 3, verify rollback restores originals.

**Files touched**: `safety/transaction.py` (new), `modes/write.py`, `tests/test_transaction.py` (new).

### Sprint 3: Harden `tlm stop` & Multi-Process Tracking (F12)

**Phase A — Plan**: Current `tlm stop` only reads one PGID. If multiple `tlm do` runs happen in parallel or if a background worker is running, they won't be tracked.

**Phase B — Build**:

1. **`safety/proctrack.py`** (new module):
   - `register_process(cwd: Path, pid: int, pgid: int, argv: list[str]) -> str` — writes to `.tlm/tmp/procs/<uuid>.json`.
   - `unregister_process(proc_id: str)` — removes the file.
   - `list_processes(cwd: Path) -> list[ProcInfo]` — reads all live proc files, prunes stale (PID no longer exists).
   - `kill_all(cwd: Path, sig: int = SIGKILL)` — kills all tracked process groups.

2. **`modes/do.py`** — replace PGID file writes with `register_process()` / `unregister_process()`.

3. **`cli.py`** — rewrite `cmd_stop_ns`:
   - List tracked processes before killing.
   - `tlm stop --signal TERM` — allow choosing signal.
   - `tlm stop --dry-run` — show what would be killed.
   - Always clean `.tlm/tmp/` staging area after kills.

**Phase C — Test**: `tests/test_proctrack.py` — mock `os.kill`, verify registration/cleanup.

**Files touched**: `safety/proctrack.py` (new), `modes/do.py`, `cli.py`, `tests/test_proctrack.py` (new).

### Sprint 4: SIGINT for Ask Streams (F17)

**Phase A — Plan**: Verify and harden `KeyboardInterrupt` handling in the ask loop. The `httpx` streaming response must be properly closed on Ctrl+C to avoid leaked connections.

**Phase B — Build**:

1. **`providers/openai_compat.py`** — audit `stream()` method:
   - Wrap the streaming iterator in a `try/except KeyboardInterrupt` that calls `response.close()`.
   - Ensure no partial JSON is left in the session on interrupt.

2. **`ask_tools.py`** — audit `run_interactive_ask`:
   - Catch `KeyboardInterrupt` during the tool loop.
   - On interrupt: save session state, print clean "interrupted" message, return gracefully.

3. **Fix B-101** (SIGINT hangs on high-latency buffers):
   - Add `httpx` read timeout of 30s on streaming connections.
   - On `KeyboardInterrupt`, use `response.aclose()` if async, or forcibly close the underlying socket.

**Phase C — Test**: `tests/test_stream_interrupt.py` — mock streaming response, simulate `KeyboardInterrupt` mid-stream, verify clean exit.

**Files touched**: `providers/openai_compat.py`, `ask_tools.py`, `tests/test_stream_interrupt.py` (new).

### Sprint 5: Auth Timeout & Session Tokens (F18)

**Phase A — Plan**: Currently, `authenticate_tier()` prompts for a password every single time `tlm write` or `tlm do` is called. Users need a "session" concept where authentication persists for N minutes.

**Phase B — Build**:

1. **`safety/auth_session.py`** (new module):
   - `AUTH_TOKEN_FILE = $XDG_STATE_HOME/tlm/.auth_token`
   - `create_auth_token(ttl_minutes: int = 30) -> str` — writes `{token, expires_at}` to the file.
   - `validate_auth_token() -> bool` — reads the file, checks expiry, returns True if valid.
   - `revoke_auth_token()` — deletes the file.
   - Token is a `secrets.token_urlsafe(32)`, file is `chmod 600`.

2. **`cli.py`** — update `authenticate_tier()`:
   - Before prompting for password, check `validate_auth_token()`. If valid, return True.
   - After successful password entry, call `create_auth_token(ttl)`.
   - Add `settings.auth_timeout_minutes: int = 30` to `UserSettings`.

3. **`tlm auth` subcommands**:
   - `tlm auth login` — authenticate and create a token.
   - `tlm auth logout` — revoke the token.
   - `tlm auth status` — show token expiry time.

**Phase C — Test**: `tests/test_auth_session.py` — create/validate/expire/revoke tokens.

**Files touched**: `safety/auth_session.py` (new), `cli.py`, `settings.py`, `tests/test_auth_session.py` (new).
